# 多语言（i18n）

界面文案全部放在外部语言文件里，`KTile.exe` 本身不含任何一句界面文字。
加一门语言 = 往 `lang/` 里放一个 JSON，不改代码、不重新编译。

- 当前内置：`zh-Hans`（简体中文）、`en`（英语）
- 首次运行跟随系统语言：系统是简体中文 → `zh-Hans`，其它一律 → `en`
- 设置 → 行为 → 语言 可随时切换，配置项是 `config.json` 的 `language`

## 1. 文件长什么样

`lang/<code>.json`，三段结构：

```json
{
  "code": "zh-Hans",
  "name": "简体中文",
  "strings": {
    "common.ok": "确定",
    "error.pluginNotFound": "找不到插件: {0}"
  }
}
```

| 字段 | 用途 |
|---|---|
| `code` | 语言代码，**必须与文件名一致**（`zh-Hans.json` → `zh-Hans`） |
| `name` | 该语言**自己**的写法（"简体中文" / "English"），设置里的下拉直接显示它 |
| `strings` | 扁平的 key → 文案。没有嵌套，key 自带命名空间 |

代码用 BCP 47 子集，不做大小写或别名归一：`zh-Hans` 就是 `zh-Hans`，
写 `zh_CN` 不会自动认成简体中文。少一层隐式约定，加语言时不容易踩坑。

## 2. 加载与回退

加载器（`src/infrastructure/i18n.cpp`）在启动时扫描 `lang/*.json`：

1. 先无条件加载 `en` 作为**兜底字典**
2. 再加载配置指定的语言（`auto` → 按系统语言换算）
3. 都拿不到 → 界面显示 key 本身

取词时的回退链是 **当前语言 → 英语 → key 本身**。漏译的后果是界面上出现
`settings.title` 这种字样——丑，但一眼能看出漏在哪儿，比空白或崩溃好排查。

`resolveLanguage()` 只负责把 `auto` 换算成具体代码，**不检查文件是否存在**：
配置里写了 `ja` 但文件被删时，生效语言回退到 `en`，而 `config.json` 里的值
不动。用户把文件放回来，下次启动就恢复，不必重设一遍。

## 3. 代码里怎么用

```cpp
#include "infrastructure/i18n.h"

// 宽字符（Win32 控件、D2D 绘制）.c_str() 直接传给 API
CreateWindowExW(..., infrastructure::i18n::trw("settings.title").c_str(), ...);

// UTF-8（数据、日志、JSON 字段）
view.error = infrastructure::i18n::tr("error.pluginDirNotReady");

// 带占位符
const std::wstring text = infrastructure::i18n::formatW(
    "error.pluginNotFound", {pluginId});     // 「找不到插件: 网速」
```

几条必须遵守的规则：

- `trw()` / `tr()` 返回的是字典里的**引用**，在下次 `setLanguage()` 之前一直
  有效。短期使用可以直接 `.c_str()`；要**存下来**（return 出去、放进成员）
  必须拷贝一份 `std::string` / `std::wstring`。
- 占位符只有 `{0}` `{1}` 这种单数字形式，替换由 `formatW` / `formatU` 做。
  不要用 `printf` 风格：语序因语言而异（`"「{0}」不能为空"` 与
  `"\"{0}\" cannot be empty"`），只有命名占位符能让译者自己调位置。
- **不要拼句子**。`tr("a") + tr("b")` 在语序不同的语言里会碎掉，
  该做的事是把整句放进一条 key，用占位符留空。
- 文件选择框（`OPENFILENAMEW.lpstrFilter`）的过滤器串是「双 NUL 结尾的
  多段串」，文案来自语言文件后必须**运行时拼**，不能写字面量：

```cpp
const std::wstring filter =
    infrastructure::i18n::trw("filter.images") + L'\0' + L"*.png;*.jpg" + L'\0' +
    infrastructure::i18n::trw("filter.allFiles") + L'\0' + L"*.*" + L'\0';
```

### 3.1 改 UI 的检查清单（每次必过）

**凡是动到界面的改动——新增窗口 / 对话框 / 控件 / 菜单项 / 提示框 / 自绘文字 /
空状态 / tooltip / 列表列头——都要按这张表走一遍。** 多语言不是"以后统一翻"，
漏一处就是英文界面里蹦一行中文。

| # | 检查项 | 怎么判断 |
|---|---|---|
| 1 | 新增的用户可见文字都进语言文件了吗 | 两份 `lang/*.json` 同时加，key 落在第 4 节的对应前缀下 |
| 2 | 两份文件的值都写了吗 | `test_i18n` **只比 key 不比内容**，英文文件里留中文占位不会被拦住 |
| 3 | 源码里还有中文字面量吗 | `grep -n '[一-龥]'`，剩下的只能是注释和第 5 节的例外项 |
| 4 | 定宽够不够 | 英文通常比中文长 1.5~2 倍。按钮 / 标签 / 列头要么实测宽度（`measureText` / `fitWidth`），要么留足余量，别按中文四字刚好放下 |
| 5 | 有没有拼句子 | `tr("a") + name` 改成一条带 `{0}` 的整句；语序交给语言文件 |
| 6 | 存下来的字符串拷贝了吗 | `trw()` / `tr()` 返回字典里的**引用**，放进成员、return 出去、塞进容器都必须拷贝 |
| 7 | 数据里存的是规范名吗 | 配置 / `items.json` 存 id 或中文规范名，**只有显示层翻译**；把译名写进数据，切语言后老配置就对不上了 |
| 8 | 切语言后会更新的界面留意了吗 | 常驻窗口（主面板、托盘）要在 `setLanguage` 后主动重设文字 / 重绘，见第 7 节 |
| 9 | 跑测试了吗 | `build.ps1 -Tests`，`test_i18n` 拦下 key 集合不一致 |
| 10 | 英文界面看过吗 | `KTile.exe --debug-shot` 导一张，或用设置窗口逐页翻一遍 |

第 4 条最容易翻车：这套布局原本是按中文四字的像素宽手工排的，加英文时
设置窗口出现过「Modifie」「ollow theme」「Double-tap C」这种半截字，
以及第二列单选框被前一列压住。改布局时**先量再定宽**，不要回头把译文截短
来迁就坐标。

`settings_window.cpp` 里现成可复用的助手（都在 `WM_CREATE` 内）：

| 助手 | 用途 |
|---|---|
| `measureText(text)` | 用对话框字体量一遍，返回 96 DPI 逻辑像素（已按 DPI 换算） |
| `fitWidth(text, min)` | 按钮宽度：文字 + 18px 内边距，不小于 `min` |
| `radioWidth(text)` | 单选框宽度：文字 + 26px（圆点 16 + 间隙） |
| `labelWidth(text)` | 紧贴控件的标签宽度：文字 + 6px |
| `formLabelW` | 整页表单标签列宽 = 这批标签里最长的一条 + 12px（下限 76） |

配套原则：**x 坐标由前一个控件的实测宽度递推**，不要写死偏移（`+98` `+72`
`+158` 这类正是上一轮裁字的来源）；想让控件「吃掉剩余宽度」要三思 ——
抑制键下拉曾经这样铺满整行，看着像把窗口横向拉开了，正确做法是按选项内容
定宽、右侧留白。

## 4. key 命名

`<模块>.<控件或场景>`，两级为主，必要时常量再往下加一层：

| 前缀 | 范围 |
|---|---|
| `common.*` | 确定 / 取消 / 名称 / 无 这类通用词 |
| `settings.*` | 设置窗口（`settings.plugins.col.name` 这类可到第四级） |
| `editor.*` | 磁贴编辑对话框 |
| `radialedit.*` `radial.*` | 轮盘编辑器 / 轮盘本身 |
| `launcher.*` | 主面板 |
| `app.*` | 托盘、启动日志、首启引导、错误框标题 |
| `error.*` | 底层抛给用户看的错误文本 |
| `builtin.*` | 内置系统项的名字（key 由 id 派生：`lock` → `builtin.lock`） |
| `theme.*` `provider.system.*` `hotkey.*` `key.*` | 皮肤名、内置数据源、热键与键名 |
| `tilemenu.*` `tab.*` `size.*` `labelmode.*` | 磁贴菜单、标签页、尺寸与标题显示方式 |

**内置项的 key 由 id 派生**，表里不写 key：`src/ui/builtin_labels.h` 把
`item.id` 拼成 `builtin.<id>` 去查。新增内置项只要在语言文件里补一条同名
条目，漏补也只是回退成 key。

## 5. 哪些文案不进语言文件

不是因为懒，而是这几类东西的性质不同：

| 保持中文（或原样） | 原因 |
|---|---|
| `app_log` / 各层 `report()` / `applog::warn` 等日志 | 开发者向诊断信息，不进界面；两套语言只会让排查时更难 grep |
| `config_store` / `json_parser` 的解析错误 | 只写日志（配置坏了就走默认值），不弹给用户 |
| `plugin_http` / `plugin_runner` 的子进程与 HTTP 细节 | 插件数据失败时界面只显示「数据不可用」，细节进日志 |
| `plugin_store` 的清单校验错误 | 面向插件作者（写 `plugin.json` 的人），与插件文档同一语言 |
| `core/builtin_items.h` 的规范名、`ui/theme.cpp` 的规范名 | **规范名是数据不是文案**：`items.json` / `config.json` 靠它索引（皮肤存 `幽夜紫`，界面显示译名）。改了老配置就对不上 |
| 字体名、`© 2026 svyee · 奇竹科技` | 专有名词 |

用户自己起的名字（磁贴名、页名、轮盘动作名）同样不跟语言切换变——那是
用户数据。默认值在**创建时**取当前语言（新建页面叫 `Page 3` 还是 `页面 3`，
看当时界面是什么语言），之后不再变。

## 6. 加一门新语言

1. 复制 `lang/en.json` 为 `lang/<code>.json`（例如 `lang/ja.json`）
2. 改 `code` 与 `name`
3. 逐条翻译 `strings`。**key 集合必须与 `en.json` 完全一致**——
   `tests/test_i18n.cpp` 会逐个文件比对，缺一条或多一条都算失败
4. 重新构建（`build.ps1` 把 `lang/*.json` 拷到 `build/lang/`），
   设置里就会多出这一项，不用改任何代码

翻译时注意：

- `{0}` 这类占位符必须保留，位置可以按目标语言语序调整
- 值为 `"—"`、`""` 这类符号的条目照抄，别翻译
- 名词长度会影响布局：设置对话框的按钮与标签列已按实测文字宽度自适应
  （见 `settings_window.cpp` 里的 `measureText` / `fitWidth`），
  但仍有不少控件是定宽的，超长语言（德语那种）需要回头调，
  优先**缩短译文**而不是改布局

## 7. 运行时切换的边界

设置里点确定后立刻 `setLanguage()`，但已经画好的窗口不会自己重写文字：

| 界面 | 生效时机 |
|---|---|
| 主面板窗口标题 | 立即（`SetWindowTextW`） |
| 托盘菜单 / 托盘提示 | 立即（每次右键都重建） |
| 主面板空状态、搜索框占位符 | 下一次重绘（切语言后会主动 `refresh()`） |
| 设置对话框自身 | 关闭后重开 |
| 其它对话框（编辑、关于、轮盘） | 下次打开 |

磁贴名、页名、轮盘动作名是用户数据，永远不跟着变。

## 8. 相关文件

| 文件 | 职责 |
|---|---|
| `lang/zh-Hans.json` `lang/en.json` | 语言文件本体 |
| `src/infrastructure/i18n.h/.cpp` | 加载、扫描、回退、取词、占位符替换 |
| `src/infrastructure/filesystem/portable_paths.cpp` | `langDirectory()`：`<exe>\lang` |
| `src/ui/builtin_labels.h` | 内置项 / 内置分组的译名（key 由 id 派生） |
| `src/ui/theme.cpp` | 皮肤规范名 → `theme.*` key；下拉显示译名、配置存规范名 |
| `src/ui/settings_window.cpp` | 语言下拉、界面/内容语言分段、控件按文字定宽 |
| `tests/test_i18n.cpp` | key 一致性、回退链、占位符、系统语言映射 |
| `build.ps1` | 把 `lang/` 拷到 exe 同级；测试模式按需附带 `i18n.cpp` |

注意 `infrastructure/i18n.cpp` **不能**依赖 `core` 以上的任何层：它是被
`infrastructure` 与 `platform/win32` 共同使用的叶子模块，只依赖
`json_parser` 与 `base/text_convert`。
